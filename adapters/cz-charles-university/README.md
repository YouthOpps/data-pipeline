# Charles University funding

This source starts at the official [Mobility Fund](https://cuni.cz/UKEN-927.html)
and follows its university's bounded
[scholarship](https://cuni.cz/UKEN-1617.html) and student-mobility funding routes.
It collects genuine named awards, funded programme overviews and dated calls.
Public summaries satisfy the website consumer limit of 600 UTF-16 code units.
The Mobility Fund summary retains its eligibility, principal grant amounts and
clock/date precision; detailed category rates and conditions remain in its
classification evidence, attributed to the same verified official page.
External administrators are represented only where Charles University's own
page gives substantive programme facts; their websites are not substituted as
publishers. This is not a crawl of every faculty, course or university archive.

## Access and source conditions

The collector uses normal public HTTPS with verified TLS and an honest project
User-Agent. Official university, Mathematics and Physics, Social Sciences
and Carolina pages were accessible during research. The initial FSV 503 recovered
on one normally paced retry. Applicable robots policies are checked per origin;
blocked paths are not requested. Tracking scripts, login/application portals,
search routes and privacy pages are not collected.

The university and faculty pages carry copyright/attribution notices. No specific
permission requirement for this normal factual collection was identified in the
reviewed public pages. Copyright is not treated as a blanket reuse licence:
records use factual metadata, original concise summaries and short factual
classification evidence, not wholesale reproduction of protected descriptions.

The university links the genuine **STARS scholarship for talented PhD students**.
Its `stars-natur.cz` detail responded HTTP200 with only an 88-byte bot-verification
cookie/reload script. That script is not executed and its verification cookie is
not set. STARS uses only the accessible university's named-award/beneficiary
facts; amount, deadline and unprovided conditions remain unknown. The same hub's
GI Bill entry explicitly identifies FSV participation for **U.S. veterans only**;
it supplies no current call or amount. Veteran eligibility is not converted into
U.S. citizenship.

Requests across all `cuni.cz` faculty subdomains share one cross-process lock,
at least 12.2 seconds between physical starts and at most five starts in any
rolling 60 seconds.
Robots, redirects, retries and the linked German DOCX count toward that allowance;
stricter robots crawl delays and backoff are honored. An overlapping test or
collection must use the same allowance. Network errors and incomplete publisher
responses fail the whole collection.

The scholarship, international, foundations, Germany, Erasmus, Carolina and MFF
inventory hubs additionally retain at least 30 seconds from the previous
inventory response completion to the next physical inventory start, including
retries and redirects. Single-programme detail pages, robots and the linked DOCX
use the physical allowance rather than an artificial pagination delay.

Every 429 saves a doubled CURRENT physical interval and inventory gap, an
increased counter and an exponential pause of at least 30 minutes (or a longer
valid Retry-After) before its body is read; the collection stops. Ordinary rate
limiting stays timed. Actual content 401/403/451 or primary visible verification
retains a refusal. Hidden text, aria-hidden="true", inline display/visibility
suppression and unrelated site chrome do not alone create a refusal. Challenges
are checked before redirect follow; robots purpose requires literal robots.txt
at every physical hop. Robots-only 4xx except 429 is unavailable REP; network,
TLS, 5xx and 429 do not become unrestricted access. Malformed timing alone creates
no permanent hold.

The original local journal path and inode remain authoritative. A separately
reviewed transition must preserve all known legacy job-completion upper bounds,
actual research/native events and stronger timers; unlogged historical holds
and 429 remain explicitly unknown. Missing or corrupt mature state fails closed.
An authenticated main workflow restores the latest exact-attempt owned inert
artifact before its data-source snapshot, and exports trusted state even if that
snapshot or collection fails. Exact run/job/source/head identities, actual job
completion chronology, artifact digest and source-code revision are validated.
Only the explicitly reviewed 31 legacy attempts may use the separately approved
full-native MAX seed; after the first new attempt a missing newest artifact cannot
fall back to an older success. The artifact contains pacing state, never records,
source bodies, headers or credentials. Native tests receive no publication token.

The 30-minute job cap and fixed daily slot remain unchanged. Collection has a
21-minute phase inside a 29-minute execution budget, with reserved export time;
stronger pacing that cannot fit fails without truncation or an automatic recrawl.

## Owned-state export failure guards

The source-local exporter invalidates safely owned stale JSON through a
validated descriptor before attempting any readiness signal. Signal open,
write or sync errors do not prevent independent cleanup attempts. A failed
export also applies this cleanup when state, run identity, implementation
validation or envelope construction fails, including a failure after a new
envelope replaces the old one. A failed signal together with failed unlink
cannot leave valid owned JSON eligible under a prior ready signal when
truncation succeeds; a failed truncation still attempts the false signal and
unlink. Every cleanup failure remains an error rather than an export success.

Artifact operations use the verified original parent descriptor and current
file identity. Replaced parents, symlinks, hard links, unsafe ownership or
permissions are refused without changing unrelated objects. Nonblocking opens
reject FIFO paths before any read can hang. Implementation hashing likewise
requires a safely owned regular file and does not follow symlinks.

## Journal ownership maintenance (#295)

parent identity and file generation. They check that authority again before
transport and export. A changed name, generation, lock or descriptor fails the
publisher gate; cleanup never adopts or truncates the stronger replacement.
Serialization, write, fsync and release failures remain sticky for the process.
Cleanup attempts independent original descriptors and preserves a prior error.
Safe owned artifact output is invalidated before best-effort signaling or
unlink; foreign descriptors and unsafe existing output are preserved.

The existing in-place journal format and transaction semantics remain in place.
The guard binds reads, writes and release to the original acquisition rather
than trusting a later pathname or recycled descriptor.
