# TU Graz master's admissions with a selection procedure

This adapter indexes the [official TU Graz master's selection calendar](https://www.tugraz.at/en/studying-and-teaching/studying-at-tu-graz/prospective-students/admission/masters-programme-with-admission-procedure) for applicants who must complete the separate selection procedure. The university lists which programmes require selection, identifies exemptions and gives programme and document requirements. The catalogue links visitors to that page for eligibility and applications. Generic master's enrolment, routes for exempt applicants, account services, application forms, documents and funding are outside this adapter's inventory.

A complete retrieval produces one record per published academic-year calendar. Its stable ID derives from the academic year, for example `at-tu-graz-msc-selection-2027-28`. The registration and document-upload window for 2027/28 opens 15 October 2026 and closes 15 December 2026. The selection commission's ranking deadline is separate. The date stays open through its final local day in `Europe/Vienna` because the source gives a calendar date without a time. The source supports Austrian host attribution and English catalogue text. Eligibility depends on the university's requirements and exemptions, so the record carries no exhaustive country list.

The [original GitHub Actions research](https://github.com/YouthOpps/ai-workspace/actions/runs/44181500355) retained two closed HTTP 200 responses, the publisher's `robots.txt` and the official admissions page. The REP rules admitted the exact route for the current and legacy crawler identities. The received page did not contain an express automation or reuse prohibition matching the approved noncommercial factual scope or an indexing denial. A linked legal notice was outside the reviewed request scope. The [subsequent GitHub Actions settlement](https://github.com/YouthOpps/ai-workspace/actions/runs/44184678694) made zero publisher requests and transferred the exact pending state after independent review of the completed original response and parser error. Runtime checks confirm current robots rules and content responses, preserve a new indexing directive or applicable policy hold, and stop on access errors without following redirects or trying alternate routes. [Source scope and decisions](https://github.com/YouthOpps/data-pipeline/issues/422)

The source workflow runs at 19:49 UTC daily, on matching main-branch pushes, and through authorized manual dispatch. It serializes requests and retains the most recent source-owned pacing state. Collection rereads the sole unpaginated document because the publisher's incremental change semantics are unverified. There is a 30-second inventory-page guard across the retained source allowance and separate physical request spacing from completed responses. The crawler never accesses the portal or submits applications.

The sole collection test runs on the reviewed isolated GitHub Actions workflow with `python -B adapters/at-tu-graz-msc-selection/test_adapter.py`. It requires the approved hosted scope and validates a full nonempty result as JSON, with no publication credential. The main-branch production workflow runs `python -B adapters/at-tu-graz-msc-selection/adapter.py --publish`. It atomically replaces only this source's data and metadata after a successful full validation, removing expired records. A complete successful retrieval can publish a filtered-empty list if the whole cohort has expired. A failed retrieval or validation keeps the previous data and success timestamp. An initial failure creates no published folder.
